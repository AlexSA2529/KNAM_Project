# Функциональные требования (ФТ)

**Версия:** 1.0
**Автор:** SA - Gusev Alexander


## Модуль интеграции с CRM

### FR-01: Загрузка контактов из CRM
**Описание:** Система должна иметь возможность по расписанию (раз в 24 часа) или по требованию загружать контакты из интегрированной CRM.
**Критерии приемки:**
- Загружаются данные: ФИО, номер телефона, ID контакта в CRM, текущий этап воронки/статус.
- Поддерживается пакетная обработка миллионов записей.
- Интеграция осуществляется через OAuth 2.0 для Bitrix24.

### FR-02: Фильтрация контактов при загрузке
**Описание:** Система должна автоматически исключать из мониторинга контакты, находящиеся на финальных этапах воронки продаж (например, "Купил", "Оплатил").
**Критерии приемки:**
- Администратор может выбрать/настроить в интерфейсе KNAM, какие статусы/этапы CRM считаются финальными и исключают контакт из мониторинга.

### FR-03: Отправка уведомлений в CRM
**Описание:** После обработки пачки сигналов система должна немедленно отправить уведомления в соответствующие CRM.
**Критерии приемки:**
- В CRM создается задача для менеджера или обновляется карточка контакта.
- Уведомление содержит информацию: "Клиент [ФИО] снова интересуется недвижимостью", источник сигнала (если доступен), кнопку для звонка.
- В карточку контакта в CRM проставляется метка "Проявил интерес" или "Требуется звонок".

## Модуль управления мониторингом

### FR-04: Настройка кастомных правил фильтрации
**Описание:** Администратор должен иметь возможность в интерфейсе KNAM задавать дополнительные правила для исключения контактов из мониторинга (например, "исключать контакты со статусом 'Не звонить'").
**Критерии приемки:**
- В UI есть раздел "Правила фильтрации".
- Администратор может создать правило, выбрав поле CRM, оператор (равно, содержит) и значение.

### FR-05: Выгрузка базы для поставщика
**Описание:** Система должна автоматически подготавливать и выгружать на SFTP-сервер поставщика файл с номерами телефонов для мониторинга.
**Критерии приемки:**
- Номера телефонов предварительно хешируются с использованием SHA-256.
- Выгрузка происходит по расписанию (раз в 24 часа) после обновления базы контактов.
- Поддерживается настройка параметров SFTP (хост, логин, ключ/пароль) для каждого поставщика.

### FR-06: Обработка входящих сигналов
**Описание:** Система должна забирать с SFTP-серверов поставщиков файлы с сигналами, обрабатывать их и сопоставлять с внутренней базой контактов.
**Критерии приемки:**
- Обработка входящих файлов запускается по расписанию (раз в 24 часа).
- Система деаномизирует сигналы, сопоставляя хеши с имеющейся базой.
- Для найденных совпадений триггерится процесс отправки уведомления (FR-03).

## Модуль аналитики и отчетности

### FR-07: Формирование дашборда
**Описание:** Система должна предоставлять дашборд с ключевыми метриками.
**Критерии приемки:**
- **Для Администратора:** Отображаются метрики: количество контактов на мониторинге, количество полученных сигналов за период, конверсия из сигнала в сделку, ROI, кол-во сигналов по источникам.
- **Для Маркетолога:** Отображается та же статистика, но все данные агрегированы и обезличены (номера телефонов скрыты, вместо них используются ID).
- Данные на дашборде обновляются не реже раза в 24 часа.

### FR-08: Генерация отчетов
**Описание:** Система должна позволять выгружать отчеты по метрикам дашборда за выбранный период.
**Критерии приемки:**
- Поддерживается выгрузка в форматах CSV и PDF.

## Модуль администрирования

### FR-09: Управление пользователями
**Описание:** Администратор должен иметь возможность создавать учетные записи для пользователей (Маркетологов) и назначать им роли.
**Критерии приемки:**
- В системе предусмотрены роли "Администратор" и "Маркетолог".
- Администратор может создать, отредактировать, деактивировать пользователя.

### FR-10: Настройка интеграций
**Описание:** Администратор должен иметь возможность добавлять и настраивать подключения к CRM и SFTP-серверам поставщиков.
**Критерии приемки:**
- UI содержит раздел "Интеграции" с формами для ввода учетных данных и параметров подключения.
